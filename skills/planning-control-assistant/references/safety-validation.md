# 安全验证参考

## 碰撞检测方法

| 方法 | 精度 | 计算量 | 适用 |
|------|------|--------|------|
| 圆形包围盒 | 低 | 极低 | 粗筛 |
| AABB | 中 | 低 | 静态障碍物 |
| OBB | 高 | 中 | 动态障碍物 |
| 凸包 | 高 | 高 | 精确碰撞 |
| 车辆几何模型 | 最高 | 高 | 最终验证 |

## 可达性分析（Reachability Analysis）

**目的**：证明在所有可能扰动下，车辆不会进入危险状态

**方法**：
1. 构造可达集（Reachable Set）：给定初始状态 + 控制约束 + 扰动，计算所有可能轨迹
2. 与障碍物集合求交：若交集为空，则安全
3. 常用工具：CORA（MATLAB）、CommonRoad

## SOTIF（预期功能安全）

**ISO 21448 关键要求**：
- 识别性能不足场景（感知局限、算法局限）
- 识别误用场景（驾驶员滥用、环境误用）
- 定义验收标准（Acceptance Criteria）

**典型 SOTIF 场景**：
| 场景 | 性能不足 | 缓解措施 |
|------|---------|---------|
| 强光直射 | 相机过曝 | 多传感器融合 + 降速 |
| 隧道出入口 | 光照剧变 | 预测性控制 + 冗余感知 |
| 异形车辆 | 训练数据缺失 | 保守策略 + 人工接管 |
| 传感器遮挡 | 部分失效 | 传感器脏污检测 + 降功能 |

## 安全验证 Checklist

- [ ] 所有规划轨迹通过碰撞检测
- [ ] 最坏情况下（全油门/全刹车）不碰撞
- [ ] 传感器失效降级策略验证
- [ ] 通信延迟场景验证
- [ ] 边界场景（极限曲率、极限速度）验证
- [ ] 人机交互（接管请求）响应时间 < 10s
