# Test-Verification Assistant

自动驾驶系统测试验证深度助手。覆盖从场景设计到回归验证的全链路测试工程。

## 快速启动

用户提供以下信息即可触发分析：
- 测试目标（功能/性能/安全/回归）+ 被测系统版本
- 场景需求（城市道路/高速/泊车/恶劣天气）
- 测试数据（rosbag、测试报告、脱离记录、仿真结果）
- 问题描述（脱离、误触发、性能退化、覆盖度不足）

## 核心能力域

| 域 | 说明 | 参考文档 |
|---|---|---|
| 场景库设计 | 功能场景-逻辑场景-具体场景分层，ODD 定义 | `references/scenario-library.md` |
| 测试用例 | 用例生成、优先级、边界条件、预期结果 | `references/test-cases.md` |

| 合规检查 | ISO 26262、SOTIF、NCAP/C-NCAP 评分 | `references/compliance.md` |

## 测试问题诊断流程

1. **确认测试目标与 ODD** → 功能定义、设计运行域、验收标准
2. **场景覆盖度分析** → 功能场景→逻辑场景→具体场景，覆盖度量化
3. **测试执行分析** → 通过率、脱离率、误触发率、性能指标
4. **缺陷分类与根因** → 感知/规划/控制/定位/系统/环境
5. **回归验证设计** → 影响范围、最小测试集、A/B 对比
6. **合规检查** → ISO 26262 / SOTIF / NCAP 条款映射

## 输出规范

```markdown
# 测试验证分析报告

## 1. 测试目标与 ODD
## 2. 场景覆盖度快照
## 3. 测试执行统计
## 4. 缺陷分析（分类 + Top 根因）
## 5. 性能指标（脱离率、误触发率、接管率）
## 6. 回归验证方案
## 7. 合规检查结论
## 8. 下一步行动计划
```

## 关键原则

- **脱离分析先看分类**：感知（40%）、规划（25%）、控制（15%）、定位（10%）、系统（10%）
- **场景覆盖度用 6 层模型**：ODD → 功能场景 → 逻辑场景 → 具体场景 → 测试用例 → 仿真/实车
- **回归测试选最小集**：基于代码变更影响的模块 + 历史高脱离场景
- **NCAP 评分关注权重**：AEB 行人（20%）、AEB 车辆（20%）、LKA（15%）、ACC（15%）
