# 底盘功能安全

一句话简介：Canbus 是 Apollo-Lite 功能安全（ASIL-D）认证的关键路径，涉及控制指令冗余校验、故障检测、降级策略和安全状态机，确保任何单点故障不会导致非预期车辆运动。

## 核心概念/原理

功能安全机制：
- **冗余校验**：控制指令双通道发送/回环校验
- **故障检测**：超时监控、信号范围检查、一致性检查
- **降级策略**：故障时分级降级（提醒 → 限制速度 → 停车）
- **安全状态机**：定义正常/降级/故障/紧急停车的状态转换

ASIL 等级：
- 底盘控制（油门/刹车/转向）通常要求 **ASIL-D**
- 底盘反馈（车速/故障码）通常要求 **ASIL-B**

## Apollo-Lite 中的实现位置

- 安全状态：`modules/canbus/vehicle_controller.cc` 的 `CheckChassisError()`
- Guardian 集成：`modules/guardian/guardian_component.cc`
- 故障检测：`modules/monitor/hardware/canbus_monitor/`

## 关键安全机制

| 机制 | 说明 | 触发条件 |
|------|------|---------|
| 指令超时 | 控制指令超过阈值未更新 | 200ms 无新 ControlCommand |
| 反馈超时 | 底盘状态超过阈值未更新 | 500ms 无新 Chassis 消息 |
| 速度异常 | 实际速度偏离目标速度过大 | 偏差 > 2m/s 持续 1s |
| 转向异常 | 实际角度偏离目标角度过大 | 偏差 > 15° 持续 500ms |
| 故障码 | 底盘系统主动上报故障 | EPS/ABS/VCU 任何非零故障码 |

## 常见问题与排查

| 问题 | 可能原因 | 排查方法 |
|------|---------|---------|
| 频繁触发安全停车 | 阈值设置过严 | 根据场景调整超时和偏差阈值 |
| 故障漏检 | 校验逻辑不完整 | 审查故障覆盖矩阵，做 FMEA 分析 |
| 降级策略冲突 | Guardian 和 Canbus 策略不一致 | 统一安全状态机定义 |

## 与其他模块的接口

- **guardian**：底盘故障触发 Guardian 安全干预
- **monitor**：底盘健康状态上报
- **control**：安全状态限制 Control 输出范围
