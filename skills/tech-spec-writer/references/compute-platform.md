## 选型决策树

```
是否需要城市 NOA（复杂场景）？
  否 → J3 / EyeQ4（L2 ADAS）
  是 → 算力需求 > 100 TOPS？
    否 → Orin N / J5（高速 NOA）
    是 → 是否需要全栈自研？
      否 → Mobileye / 华为（封闭方案）
      是 → Orin X / Thor / J5（开放生态）
```

## 算力评估方法

**模型算力需求估算**：
```
总需求 = Σ(各模型 FLOPs × 帧率 × 精度系数)

精度系数：
- FP32: 1.0x
- FP16: 0.5x
- INT8: 0.25x（注意：部分层需 FP16）

预留：
- 功能扩展: +30%
- 系统开销: +20%
- 峰值缓冲: +20%
- 总计预留: +70%
```

**示例**：
```
BEVFusion: 500 GFLOPs × 10 FPS × 0.25 = 1250 GFLOPS
CenterPoint: 100 GFLOPs × 10 FPS × 0.25 = 250 GFLOPS
规划控制: 10 GFLOPs × 20 FPS × 0.5 = 100 GFLOPS
总计: 1600 GFLOPS ≈ 1.6 TOPS
Orin X 利用率: 1.6 / 254 = 0.6% → 严重过剩

实际考虑 TensorRT 优化后：
BEVFusion 可能只需 20-40 TOPS 有效算力
```

## 功耗与散热

| 平台 | TDP | 散热方案 | 典型车型 |
|------|-----|---------|---------|
| Orin X | 60W | 主动风冷/液冷 | 中高端 |
| J5 | 30W | 被动散热+风冷 | 中端 |
| J3 | 2W | 被动散热 | 低端 |

**散热设计要点**：
- 环境温度 85°C 时，芯片结温 < 105°C
- 散热片热阻 + 风扇风量需匹配 TDP
- 液冷方案：水冷板 + 水泵 + 散热器
