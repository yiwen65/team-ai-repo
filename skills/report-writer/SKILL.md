# Report Writer

自动驾驶项目技术汇报深度助手。提供不同层级、不同场景的专业汇报结构。

## 快速启动

用户提供以下信息即可生成汇报：
- 汇报对象层级（工程师/TL/总监/VP/CTO）
- 汇报场景（进度/方案/问题/成果/评审）
- 核心内容（数据、结论、风险、需求）
- 时间限制（5min / 15min / 30min / 60min）
- 输出形式（Markdown / PPT 大纲 / 邮件 / 文档）

## 核心能力域

| 域 | 说明 | 参考文档 |
|---|---|---|
| 进度汇报 | 里程碑、阻塞、风险、资源需求 | `references/progress-report.md` |
| 技术方案 | 背景、选型、架构、验证、计划 | `references/tech-proposal.md` |
| 问题复盘 | 现象、根因、影响、修复、预防 | `references/postmortem.md` |
| 成果展示 | 突破、数据、对比、价值、下一步 | `references/achievement.md` |
| 评审答辩 | 质疑预判、数据准备、备选方案 | `references/review-defense.md` |
| 跨团队沟通 | 对齐目标、明确接口、协调依赖 | `references/cross-team.md` |

## 汇报层级适配

| 层级 | 关注重点 | 语言风格 | 数据深度 |
|------|---------|---------|---------|
| 工程师/TL | 技术细节、实现方案、阻塞问题 | 专业术语、代码级 | 详细 |
| 总监 | 进度、风险、资源、团队状态 | 结构化、指标驱动 | 中等 |
| VP | 商业价值、竞争态势、战略对齐 | 高层视角、趋势 | 精选 |
| CTO/CEO | ROI、技术路线、投资决策 | 简洁、结论先行 | 极少 |

## 时间适配

| 时长 | 结构 | 页数/字数 |
|------|------|----------|
| 5min（电梯演讲） | 1 结论 + 2 支撑 + 1 需求 | 3-5 页 |
| 15min（例会） | 背景 + 进展 + 问题 + 下一步 | 8-12 页 |
| 30min（专题） | 完整结构 + 详细数据 + Q&A | 15-20 页 |
| 60min（评审） | 完整方案 + 对比分析 + 风险 + 详细 Q&A | 25-35 页 |

## 输出规范

所有汇报材料默认结构：

```markdown
# [汇报标题]

## 1. 一句话结论（TL;DR）
## 2. 背景与目标（为什么做）
## 3. 核心内容
   - 进展/方案/问题/成果
   - 关键数据（量化）
## 4. 风险与挑战
## 5. 下一步/资源需求/决策点
## 6. Q&A 预判（针对评审场景）
```

## 关键原则

- **结论先行**：前 30 秒必须给出核心结论，不要铺垫
- **数据说话**：每个观点必须有量化支撑，"感觉"和"应该"是大忌
- **风险不隐瞒**：主动暴露风险比被问到更可信，但要带解决方案
- **一页一主题**：每页/PPT 只讲一个观点，不要堆叠
- **Q&A 要预判**：提前准备 5-10 个最可能被问到的问题和答案
- **不同对象不同版本**：给 CTO 的 5 页版本和给工程师的 20 页版本，内容相同但深度不同
