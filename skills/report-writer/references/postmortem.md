# 问题复盘汇报参考

## 复盘模板（5 Whys + 改进）

```markdown
# [事故/问题] 复盘报告

## 1. 事故摘要（一句话）
2026-05-20 14:30，测试车在城市道路 AEB 误触发，紧急制动导致后车追尾。

## 2. 时间线
| 时间 | 事件 |
|------|------|
| 14:29:55 | 车辆接近井盖，相机检测为障碍物 |
| 14:29:58 | 感知置信度 0.92，触发 AEB |
| 14:29:59 | 车辆紧急制动，减速度 -6 m/s² |
| 14:30:02 | 后车追尾，无人员受伤 |

## 3. 影响
- 测试车：后保险杠损伤
- 测试计划：暂停 2 天
- 声誉：需内部通报

## 4. 根因分析（5 Whys）
1. **为什么 AEB 误触发？** → 感知将井盖分类为障碍物
2. **为什么井盖被错分？** → 训练数据缺少井盖样本（< 50 张）
3. **为什么数据不足？** → 数据采集策略未覆盖低矮障碍物
4. **为什么策略缺失？** → 场景覆盖度评估未包含"路面异物"
5. **为什么评估不完整？** → 场景库建设以 VRU 和车辆为主，忽略静态障碍物

**根因**：场景覆盖度评估不完整，缺少"路面异物"类别。

## 5. 修复措施
| 措施 | 负责人 | 截止时间 | 状态 |
|------|--------|---------|------|
| 补充井盖/路面异物数据 1000+ 张 | 数据团队 | 2026-06-01 | ⬜ |
| 增加路面异物分类 | 感知团队 | 2026-06-15 | ⬜ |
| 更新场景库覆盖度评估表 | 测试团队 | 2026-05-30 | ⬜ |
| AEB 增加高度过滤（< 20cm 不触发） | 规划团队 | 2026-06-01 | ⬜ |

## 6. 预防措施
- [ ] 场景库每月 review，补充新发现盲区
- [ ] 误触发案例自动进入高优先级数据采集队列
- [ ] AEB 触发增加多帧确认（3 帧连续检测）

## 7. 经验教训
- 场景覆盖度不能仅依赖已知类别，需要持续从误触发/脱离中挖掘
- AEB 触发逻辑需要保守，宁可漏检也不误触发（安全优先）
- 测试车保险和事故处理流程需要完善
```

## 汇报技巧

- **不甩锅**：即使根因在别的团队，也要用"我们"而不是"他们"
- **时间线要精确**：到秒级，证明调查充分
- **改进措施要可验证**：每条都有负责人和 deadline
- **根因要到系统层面**：不要停在"某人做错了"，要到"流程/机制缺失"
- **同类问题检查**："其他车型/模块是否也有类似问题？"
